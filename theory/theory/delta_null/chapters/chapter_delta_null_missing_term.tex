\chapter{Checking the rarest symbol first}

\noindent\textbf{This chapter is a conjecture.} Comparing a pattern's symbols in order of rarity is an established idea in string search. Sunday's optimal mismatch algorithm compares the pattern's characters in increasing order of how often they occur, so that a mismatch is found as early as possible \cite{src:Sunday-1990}. In the engine, ordering probes by rarity needs no logarithm and never changes the count (orior \texttt{1044ca6}, \texttt{src/\allowbreak{}engine/\allowbreak{}c/\allowbreak{}engine/\allowbreak{}orior.h:284-288}, \texttt{:960-964}). Whether rarity makes the search faster depends on the data, and the engine's table does not separate it out. The table's reorder column ranks probes by how many candidates each one leaves, given the probes already placed, while \texttt{anchor\_steer\_probe\_order} ranks them by rarity alone (\texttt{:712-723}). Over 65513 alignments with a pattern of length 24, that reorder changes the reads per alignment from 1.877 to 1.875 on the skewed data, where placing probes by candidates left reaches 1.067. It changes them from 1.562 to 1.002 on the synthetic skewed data and from 1.187 to 1.000 on data with period 16. No ordering moves the uniform data from 1.003 (\texttt{docs/\allowbreak{}steering.md:244-\allowbreak{}252}). Probes are placed by greedy maximum coverage, which drops at least \(1 - 1/e\) of what the best set of the same number of probes drops \cite{src:Nemhauser-Wolsey-and-Fisher} (\texttt{orior.h:783-796}). A rarity order counted on one set of data does not carry over to another (\texttt{:408-413}).

\section{The conjecture}

The order in which the probes are checked is the only choice left to make, and the goal is to drop a candidate in as few checks as possible. Ordering the probes by the frequency of their symbols in the data makes that choice.

Take a pattern with three positions, \(A = \{a_1, a_2, a_3\}\), whose symbols have these probabilities in the data:

\begin{center}
\begin{tabular}{lll}
\toprule
position & symbol & probability \\
\midrule
\(a_1\) & common & 0.40 \\
\(a_2\) & medium & 0.08 \\
\(a_3\) & rare & 0.001 \\
\bottomrule
\end{tabular}
\end{center}

Checked in order of rarity, the search compares \(a_3\) first, then \(a_2\), then \(a_1\).

A common symbol is a poor first check. The data holds it often. Most candidates pass it. A rare symbol is a good first check, because almost every candidate fails it at once. The chance that the first check drops a candidate is
\[
\Pr(\text{dropped at the first check}) = 1 - P\bigl(x(a_{\text{rare}})\bigr).
\]
If the rarest symbol has probability 0.001, the first comparison drops 99.9\% of all candidates.

The order changes nothing about which places are matches. Each check is still exact, and failing any check still rules a place out for good, \(\neg\,\mathrm{Anc}_A(s) \Rightarrow \neg\,\mathrm{Occ}(s)\). The frequencies only decide which check runs first. The data's own statistics steer the search, and the rarest probes clear most of the candidates before the processor reaches the loop over them.
